# AITL Heuristic System

A self-maintaining customer-support policy. Inference is pure Python;
maintenance is a Claude Code coding agent.

This system is a **Heuristic System (HS)** in the sense of Weng 2026
(《Learning Beyond Gradients》). The Chinese definition requires seven
components, each existing as a real, inspectable artifact:

| HS component (Chinese) | File / mechanism                                     |
|------------------------|------------------------------------------------------|
| 程序策略                | `policy.py`                                          |
| 状态表示                | `detectors.py`                                       |
| 反馈入口                | `aitl_hl.py` (ask · report · replay · paraphrase_check) |
| 实验记录                | `trials.jsonl` + `summary.csv` (derived)             |
| 回放 / 测试              | `golden.jsonl` + `paraphrases.jsonl`                 |
| memory                 | `memory.md` + git log                                |
| 更新机制                | `/aitl-update`, `/aitl-simplify`, `/aitl-paraphrase` |

The Chinese is explicit: **单条 rule 不够** — a single rule is not an HS.
Rules, feedback, history, and the next update path must all connect. This
CLAUDE.md is what makes them connected.

## Invariants (never violate)

1. **Pure-Python policy.** `policy.py` and `detectors.py` use stdlib only,
   plus `from detectors import ...` in `policy.py`. No network, no LLM,
   no third-party packages, ever. If a fix would require any of these,
   stop and tell the user — that means the rule layer is not the right
   layer.

2. **Append-only history.** `trials.jsonl`, `golden.jsonl`, and
   `paraphrases.jsonl` are append-only. Never delete or rewrite a row.
   The project `.claude/settings.json` denies edit on these — if you find
   yourself wanting to edit one, you've taken a wrong turn. `summary.csv`
   is **derived** from `trials.jsonl` and regenerated by `aitl_hl.py`
   after every trials append; never edit it by hand.

3. **All-green report ends every edit.** Every edit ends with
   `python aitl_hl.py report` showing:
   - regression: N/N passing
   - paraphrase: N/N consistent (if any paraphrases exist)

4. **Failed directions get written down.** If you abandon a direction
   (e.g. a fix that would break a golden, an over-narrow regex that helps
   one trial but hurts three), append the reason to `memory.md` under
   "Failed directions" so the next round doesn't retry it.

5. **Mandatory compression.** After every 5 accepted `/aitl-update` runs,
   run `/aitl-simplify` before accepting more rules. An HS that only
   grows becomes a ball of mud.

6. **Generalize, don't memorize.** A fix that only works on the literal
   query string is a bug. Broaden the regex in `detectors.py`, or add a
   new intent. If the queries share a real pattern, find it.

7. **Close the loop.** Every maintenance skill (`/aitl-update`,
   `/aitl-simplify`, `/aitl-paraphrase`) ends by calling
   `python aitl_hl.py record --skill <name> --trial-name <label> --notes <why> --files <what>`.
   This writes a `kind: "eval"` row to `trials.jsonl` (with `score_mean
   = regression_pass / regression_total` and an `inferences` count) and
   regenerates `summary.csv`. `--trial-name` is a hypothesis label
   following the article's convention (e.g. `update_v3_broaden_return_regex`,
   `simplify_v1_collapse_response_dict`) — it is the agent's primary
   key into its own memory next round.

8. **Auto-simplify on new best_score.** After `/aitl-update` records
   an eval, it must run `python aitl_hl.py is_new_best`. If that prints
   `yes` (exit 0), `/aitl-simplify` is invoked before the update skill
   exits. The shipped `policy.py` is always the simplest version that
   holds the current best — the Atari57 prompt rule, mechanized.

## Files at a glance

- `policy.py` — `respond(q: str) -> str`. Edit freely (within invariant 1).
- `detectors.py` — `intent(q)`, `urgency(q)`. Add new detectors as needed.
- `aitl_hl.py` — driver. Don't edit unless changing the feedback surface.
- `trials.jsonl` — every served query + every maintenance run, append-only.
  Three kinds: `ask` (human query), `eval` (post-edit policy eval),
  `probe` (exploratory inference; no score).
- `summary.csv` — flat view derived from `trials.jsonl`; never hand-edited.
- `STATUS.md` — human-readable snapshot derived from `trials.jsonl`;
  never hand-edited. The continual-system analog of the article's per-run
  README.md. Read this first for a one-glance view of system state.
- `golden.jsonl` — accepted answers, the hard regression set, append-only.
- `paraphrases.jsonl` — multi-seed robustness set, append-only.
- `memory.md` — agent-maintained design notes and failure log.

## Optional tool: probe

When you're about to edit `detectors.py` or `policy.py` but aren't sure
whether your hypothesis about the failure mode is correct, run:

```bash
python aitl_hl.py probe \
  --trial-name "<hypothesis_label>" \
  --notes "<what you're investigating>" \
  --queries "q1" "q2" "q3" ...
```

This runs `respond()` on each query, prints the result, and appends a
`kind: "probe"` row (no score, but inferences counted). Use it to verify
detector coverage on synthetic queries before committing to an edit. The
article's Breakout artifact has 6 probe rows for exactly this purpose
(action probes, RAM correlation probes, etc.).

## Workflow

```text
python aitl_hl.py ask        # human serves queries, annotates
python aitl_hl.py report     # see the agent feedback buffer
/aitl-update                 # Claude Code rewrites policy/detectors
python aitl_hl.py replay     # verify regressions
(every 5 cycles) /aitl-simplify
(periodically)   /aitl-paraphrase
```
